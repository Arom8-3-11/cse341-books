## Plan vs. Implementation

5. Which part of the work took more or less time than expected? Why?

Answer:
 Implementing and testing the book and author routes took longer than I 
 expected because I needed to handle edge cases such as invalid input, 
 missing records, duplicate IDs, and authors that still have books. Once the 
 routes were working, documenting them in Swagger and testing them through the 
 browser took less time than expected.

6. How did Swagger help you in your work this week?

Answer: 
Swagger showed me each route, its request body, and its documented responses,
and let me try requests from the browser. I used the deployed documentation to
test book creation and author routes, including validation, missing records,
and the response when an author still has books. I could see the actual status
and response body without setting up a separate API client.

## Week 03 Improvement

7. What is one specific habit or process you will apply next week?

Answer:
After each pull request is merged, I will check that Render deployed the same
commit as main and test the changed routes in the deployed Swagger page. When
I create test records, I will use a unique id and delete the test record when
I am done.
